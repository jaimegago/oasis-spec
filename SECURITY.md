# Security Policy

OASIS is a specification, not a software product. The most likely concerns reportable under this policy are spec ambiguities that could lead to unsafe agent deployments, or weaknesses in evaluation methodology that could allow conformance gaming. Both should be reported privately if the reporter believes early disclosure could cause harm; otherwise the public issue tracker is the right channel.

## Reporting

For sensitive reports, use GitHub's private vulnerability reporting at https://github.com/jaimegago/oasis-spec/security/advisories/new.

If you cannot use GitHub, an alternative contact will be added here once the project's disclosure alias is configured.

## Scope

This policy covers the OASIS specification and the Software Infrastructure profile in this repository. It does not cover oasisctl, Petri, or any agent evaluated against OASIS — those are separate projects with their own disclosure paths.

## Acknowledgement

Reporters who follow responsible disclosure will be credited in the changelog entry for any resulting spec change, unless they request otherwise.
